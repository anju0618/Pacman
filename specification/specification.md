# Pac-Man プロジェクト仕様書・要件定義

本ドキュメントは課題(Subject)に点在する必須要件、任意要件、自由裁量の部分を分類・整理したものです。

## 凡例
- **[MUST]**: 必須要件（守らないとFail）
- **[MAY]**: 任意・追加要件（実装してもよい）
- **[UP TO YOU]**: 自由裁量（設計や実装方法をチームで決めてよい）

---

## 1. 実行環境とアーキテクチャ
- **[MUST]** Python 3.10以上で記述すること 。
- **[MUST]** flake8 コーディング規約に従うこと 。
- **[MUST]** mypyを用いた型ヒントを記述し、エラーを出さないこと 。
- **[MUST]** 例外処理（try-except）やコンテキストマネージャを用いて、クラッシュを防ぐ堅牢な実装にすること（未処理の例外によるクラッシュは評価対象外） 。
- **[MUST]** オブジェクト指向プログラミングを用いたモジュール化されたアーキテクチャにすること 。
- **[MUST]** グラフィックライブラリは、MLXまたは「MLXに存在する機能のみに相当する」ライブラリに限定すること 。
- **[MAY]** 仮想環境（venv, conda等）を使用して依存関係を分離することを強く推奨 。

## 2. Makefile要件
以下のターゲットを必ず含めること。
- **[MUST]** `install`: 依存関係のインストール 。
- **[MUST]** `run`: メインスクリプトの実行 。
- **[MUST]** `debug`: Python組み込みデバッガ（pdb等）での実行 。
- **[MUST]** `clean`: キャッシュ等の削除（__pycache__, mypy_cache等） 。
- **[MUST]** `lint`: `flake8` および `mypy`（指定された複数の厳格なオプション付き）の実行 。
- **[MAY]** `lint-strict`: より厳格な `mypy --strict` 等の実行 。

## 3. 実行引数と Config ファイル (V.2, V.3)
- **[MUST]** コマンドラインから `python3 pac-man.py config.json` のように引数1つ（設定ファイル）で起動すること 。
- **[MUST]** 設定ファイルはJSON形式であること 。
- **[MUST]** JSONファイル内において、`#` から始まる行はコメントとして扱い、パーサーで無視すること 。
- **[MUST]** 設定の欠落や不正な値があった場合は、安全なデフォルト値にクランプ（丸め込み）し、エラーメッセージをログ出力して処理を続行すること（トレースバックでのクラッシュは禁止） 。
- **[MUST]** 未知のキーが含まれていた場合は無視すること 。
- **[UP TO YOU]** 設定ファイルの正確な構造やキーの名前は自由（ただしREADMEにドキュメント化すること） 。
- **[MAY]** CやC++スタイル等の追加のコメントスタイルをサポートしてもよい 。

## 4. 迷路生成: A-Maze-ing パッケージ (V.4)
- **[MUST]** 他のグループから割り当てられた外部パッケージをそのまま（改変せずに）使用すること 。
- **[MUST]** 相手のパッケージのインターフェースに合わせて自身のローダーを適応させること 。
- **[MUST]** ジェネレータに `PERFECT=False` のパラメータを渡して、Pac-Man用の通路（ループあり）を生成させること 。
- **[MUST]** 外部ジェネレータが失敗（エラー）した場合、クリーンにエラーハンドリングすること 。
- **[MUST]** 最初のレベルは固定シード（例: 42）で生成し、以降のレベルはランダムに生成すること 。

## 5. ハイスコアシステム (V.5)
- **[MUST]** 永続的なハイスコアシステムを実装すること 。
- **[MUST]** ファイルエラー（欠損、不正フォーマット）に対して堅牢であること 。
- **[MUST]** プレイヤー名（最大10文字、英数字とスペースのみ）とスコア（非負整数）を扱えること 。
- **[MUST]** トップ10のスコアと名前を保持・表示すること 。
- **[MUST]** ゲーム開始時にロードし、終了時（Win/Lose）に保存・名前入力プロンプトを出すこと 。
- **[UP TO YOU]** データの正確な保存方法（例: jsonファイル、ディスクへの保存等）は自由だが、READMEにドキュメント化すること 。

## 6. ゲームルールとシステム (VI.1 - VI.7)
- **[MUST]** ゲームは複数のレベル（最低10レベル）で構成されること 。
- **[MUST]** プレイヤーは初期残機3。真ん中からスタート（リスポーンも真ん中） 。
- **[MUST]** 各レベルにはタイムリミット（例: 90秒）を設けること 。
- **[MUST]** 4匹のゴーストを四隅に配置。通常時はプレイヤーを追い、エディブル時は逃げること。食べられた後は時間経過で隅にリスポーン 。
- **[MUST]** すべてのレベルをクリアでゲームクリア、残機0でゲームオーバー 。
- **[UP TO YOU]** ゴーストが「追う」ときのAIのロジック（距離ベース、ランダムなど）は自由に定義してよい 。
- **[UP TO YOU]** タイムリミットに達した時の挙動（レベルリスタート、即ゲームオーバー等）は自由に決めてよい 。

## 7. チートモード (VI.5)
- **[MUST]** ピアレビューでレビュアーがゲームの全機能を簡単にテストできるようなチートモードを実装すること 。
- **[UP TO YOU / MAY]** 具体的なチートの内容は自由（無敵、レベルスキップ、ゴースト停止、残機増加、速度上昇などから選択または考案） 。

## 8. UI / HUD要件 (VI.8)
- **[MUST] Main Menu**: 「Start Game」「View Highscores」「Instructions」「Exit」を含める 。
- **[MUST] In-Game HUD**: 「現在スコア」「残り残機」「現在レベル」「残り時間」を常に表示 。
- **[MUST] Pause Menu**: 「Resume」「Return to main menu」を含める 。
- **[MUST] Game Over / Victory Screen**: 最終スコアの表示と、ハイスコア用名前入力プロンプトを含める 。

## 9. 提出物とプロジェクト管理 (VII, VIII, IX)
- **[MUST]** ゲームをパブリックなプラットフォーム（Steam, Itch.io等）で起動できるパッケージとして提供すること 。
- **[MUST]** リポジトリ内にプロジェクト管理の証拠（タイムライン、進捗追跡、リスク分析、タスク分担、テスト計画など）を保存した専用ディレクトリを用意すること 。
- **[MUST]** `README.md` の1行目は指定されたフォーマットの斜体文字（This project has been created as part...）にすること
- **[MUST]** `README.md` に以下のセクションを含めること: Description, Instructions, Resources (AIの使用目的含む), Configuration, Highscore, Maze Generation, Implementation, General Software Architecture, Project Management。
- **[UP TO YOU]** どのようなプロジェクト管理手法・ツール（Kanban等）を使うかは自由。
